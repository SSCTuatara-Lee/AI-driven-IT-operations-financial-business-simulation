# 交易超时与幂等重试

版本：1.0；适用：本项目模拟交易 API。

## 现象
客户端收到 RESPONSE_TIMEOUT 或网络超时，但账户可能已经发生变动。

## 验证
1. 保留原请求的 Idempotency-Key 和请求正文。
2. 在交易中心输入幂等键查询；或调用 GET /api/trades?q=<原幂等键>。
3. 按 trace_id 关联日志，检查同一交易是否存在 LEDGER_COMMITTED。
4. SUCCEEDED 表示已成功记账，REJECTED 表示业务拒绝。未查到记录时不能仅凭这一点推定最终失败，应继续核查或用原键和原正文重试。
5. 用原幂等键和完全相同的内容重试，不会再次产生分录。同一键更换内容会被拒绝。

## 恢复验证
运行账务对账，检查借贷分录平衡、账户余额与分录一致；支付退款累计不超过原支付金额。

## 本地演练
启动“记账后响应丢失”，发送支付交易，观察 504。保留原幂等键重试应返回同一笔成功交易，并标记 replayed=true。
