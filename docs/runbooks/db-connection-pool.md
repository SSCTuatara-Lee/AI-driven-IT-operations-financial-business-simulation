# 应用数据库连接池耗尽：排查手册样例

文档 ID：RB-DB-001  
版本：0.1-draft  
适用范围：模拟交易应用；连接池实现、数据库版本与查询命令待工程选型后补齐。  
状态：通用排查模板，尚未在目标环境验证。

## 现象

交易接口耗时升高，出现获取数据库连接超时；连接池等待请求增加。仅出现连接超时不能确认根因是“连接池配置过小”。

## 需要的现场信息

- 故障时间范围、受影响服务、实例、交易编号及 trace_id。
- 连接池上限、活跃连接数、空闲连接数、等待请求数与连接获取耗时。
- 同一时间段数据库可用性、连接数、慢查询、锁等待与资源情况。
- 调用链中连接获取、SQL 执行和外部请求各阶段的耗时。
- 故障前后的负载变化、配置变更及实例数量变化。

## 排查步骤

1. 确认数据库能否从应用所在网络访问，区分无法建连与连接池已满。
2. 对齐应用实例和时间范围，确认活跃连接是否持续达到上限及等待数是否同步升高。
3. 查看长事务、慢 SQL 和锁等待；若存在，优先分析连接被长期占用的原因。
4. 检查连接释放路径和异常处理，判断是否有连接泄漏。
5. 检查是否在持有数据库事务时等待外部网络调用。
6. 对比请求负载与实例扩缩容，核算应用连接总预算与数据库容量。

## 临时缓解与恢复

可在实验环境停止引起争用的测试任务、降低压测流量或回退已确认的问题变更。具体终止会话、重启实例、调整连接上限等动作需结合事务状态与容量评估，不能只依据本模板执行。

恢复后验证连接等待消退、交易延迟与错误率回落，并核对超时交易最终状态、账务平衡及幂等重试结果。

## 根因结论模板

- 结论：候选原因与已确认事实分别描述。
- 证据：列出日志/指标/追踪/数据库观测的标识与时间。
- 反证：记录与候选原因矛盾的信息。
- 缺失信息：说明哪些证据尚未取得。
- 下一步：给出能区分候选原因的验证动作。
