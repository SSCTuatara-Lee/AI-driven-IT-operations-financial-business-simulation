# 当前架构与后续迁移

更新：2026-09-28。首期范围已确认并实现代码：Python、本机优先、MySQL 兼容接入、支付交易闭环与 AI 运维。GTP 已取消。数据库目标为 TDSQL MySQL，用户提到赤兔管理平台；具体版本与实例尚未提供。

## 运行结构

浏览器 → FastAPI API → 账户/交易/账务模块 → SQLAlchemy → SQLite（本机）或 MySQL（Docker）。

同一应用中的运维模块 → 日志索引与 Prometheus 指标 → 规则诊断 → 知识库检索 → 可选兼容模型 API → 带原文引用的问答。

本期采用单应用、单进程，代码按模块分开。暂未拆成多个微服务，未接入真实 Linux/CCE/TDSQL 采集。

## 数据与交易

账户、交易、分录、日志、演练、文档、检索片段和会话使用关系数据库持久化。金额存整数分。业务账户余额与双边分录在同一事务中提交，系统清算账户作为充值提现对手方。原支付记录锁保护累计退款额度，幂等键与规范请求摘要绑定。

业务拒绝保存 REJECTED 交易但不写资金分录；请求格式错误返回 422；模拟依赖失败发生在记账之前；响应丢失演练发生在事务提交之后。查询与幂等重试是处理不确定响应的依据。

## 故障与证据

演练限于应用层：下游延迟、依赖不可用、连接获取超时、记账后响应丢失。每次演练只有一个活动目标，在请求入口检查截止时间，停止或到期后新请求不再注入。

诊断器仅读取业务及运行事件，不读取演练类型。证据包含时间、服务、Trace ID、交易编号、事件类型和耗时。根因输出属于可核验候选，尚未实现从真实主机/数据库指标推导底层根因的引擎。

## 知识与对话

手册按版本保存，分块建立关键词索引；配置 Embedding 后生成向量并混合检索。每次回答保留片段 ID、标题、版本与原文快照。无模型时展示检索结果；模型错误时明确降级。文档更新删除会同步处理索引，历史会话保留当时引用快照。

## 部署演进

本机 SQLite 用于立即启动与开发测试；Docker 配置使用 MySQL 8.0，并有可选 Prometheus。CCE 清单仅是迁移模板。TDSQL 接入前需核验 SQL、内核、TLS、连接预算、分片和事务约束，并使用真实环境重跑资金一致性与故障测试。

后续可增量加入 Linux 节点指标、数据库指标、OpenTelemetry Collector、真实容器演练、多用户权限、独立向量存储及数据库迁移机制。云资源、真实模型调用和生产化能力尚未验收。
